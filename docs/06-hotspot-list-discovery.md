# 热点列表检索与排序方案

> 状态：已实现。
>
> 本方案只改善当前扫描快照的人工浏览，不改变采集、AI 判定、入库或来源质量策略。

## 1. 目标

热点列表保持单一情报流，避免按关键词拆分后难以横向比较。为减少控制项，只保留最常用的定位方式：找某个主题、看某类来源、按时间或相关性排序。

第一版不增加时间范围、具体站点多选、评分门槛或看板分组。相关性和可信度继续显示在卡片上，供人工判断。

## 2. 控件

列表工具栏只保留四项：

| 控件 | 行为 |
| --- | --- |
| 搜索 | 沿用现有全文搜索：标题、摘要、来源和监控词。 |
| 来源 | 沿用现有单选：全部、RSS、网页、X/Twitter。 |
| 监控词 | 新增单选下拉：全部监控词或一个启用中的监控词。 |
| 排序 | 新增单选下拉：最新或最相关。 |

不增加具体来源站点、多个评分阈值或多选条件。需要找特定站点时，直接使用现有搜索框。

## 3. 默认行为

| 控件 | 默认值 |
| --- | --- |
| 搜索 | 空 |
| 来源 | 全部 |
| 监控词 | 全部监控词 |
| 排序 | 最新 |

“最新”按 `publishedAt` 从新到旧排序。网页来源会从文章页的结构化元数据、JSON-LD、`<time>` 和唯一可见日期中提取真实发布时间；抓取短暂失败时会重试一次。无法取得可解析原文发布时间的条目统一显示“时间未知”，并排在所有已知时间条目之后；不使用系统发现时间替代原文发布时间。

“最相关”按 `relevanceScore` 从高到低排序；同分时保留服务端原始顺序。可信度不单独排序，避免把评分选择变成又一个决策点。

## 4. 筛选组合

搜索、来源和监控词采用交集：一条热点必须同时匹配所有已选条件才显示。

- 改变搜索、来源、监控词或排序后，自动回到第一页。
- 顶部数量显示当前结果数。
- 有非默认筛选时，提供一个简短的“重置”操作，恢复到默认浏览状态。
- 新扫描完成后，保留当前筛选和排序；若没有匹配项，空状态提供“重置”操作。

## 5. 实现边界

第一版只在前端处理当前已加载的最多 100 条热点：

1. 使用现有 `searchQuery` 和 `sourceFilter`。
2. 新增单个 `keywordFilter` 与 `sortMode` 状态。
3. 先筛选、再稳定排序、最后分页。

不需要新增 API 参数、数据库字段或索引。

## 6. 验收标准

- [ ] 工具栏仅有搜索、来源、监控词和排序四项主要控制。
- [ ] 用户可只查看一个监控词的热点。
- [ ] 用户可按 RSS、网页或 X/Twitter 查看热点。
- [ ] 用户可在“最新”和“最相关”之间切换排序。
- [ ] 默认按发布时间从新到旧展示，时间未知条目排在最后。
- [ ] 搜索、来源和监控词可正确组合，变化后回到第一页。
- [ ] 重置后恢复“全部监控词、全部来源、最新排序、空搜索”。
- [ ] 桌面和移动端工具栏没有文本溢出、控件遮挡或横向滚动。
