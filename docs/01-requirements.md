# Hot Monitor 需求说明

## 1. 产品目标

Hot Monitor 面向 AI 编程内容创作者，自动发现指定关键词相关的真实热点，并在热点出现后及时通知用户，减少人工搜索成本。

## 2. 用户与核心场景

用户可以：

- 创建、暂停、恢复和删除监控关键词。
- 为每个关键词设置监控范围和最低可信度。
- 手动触发一次扫描。
- 按时间和热度查看热点情报。
- 查看来源、AI 摘要、相关性、可信度和判定理由。
- 在站内实时接收新热点通知。
- 配置邮箱后接收邮件通知。

默认监控间隔为 30 分钟。

## 3. 信息来源

系统采用多来源策略，避免依赖单一来源：

- 网页搜索结果和公开网页内容。
- RSS、官方博客和产品更新日志。
- X/Twitter 信息，通过 `twitterapi.io` 适配器接入。

每个来源必须保留原始 URL、来源名称、抓取时间和原始文本摘要。

## 4. AI 识别要求

DeepSeek 用于：

- 判断内容是否与关键词相关。
- 判断内容是否是事实陈述、可靠报道、转载、营销内容或疑似假冒消息。
- 综合来源可信度、内容一致性和发布时间输出可信度分数。
- 生成中文标题、摘要、关键事实和判定理由。

AI 输出必须是可校验的 JSON。解析失败或 AI 服务异常时，内容不得被标记为高可信热点。

## 5. 通知要求

- 新热点入库后，立即通过 Socket.IO 推送给在线页面。
- 对达到通知阈值的热点发送邮件。
- 同一热点在同一关键词下不得重复通知。
- 页面显示未读数量，支持标记已读。

## 6. MVP 范围

第一版包含：

- 响应式 Web 控制台。
- SQLite 持久化。
- 关键词管理。
- 多来源采集适配器。
- DeepSeek 真实性和相关性判定。
- 30 分钟定时任务和手动扫描。
- Socket.IO 实时站内通知。
- SMTP 邮件通知配置。
- 基础测试和验收数据。

暂不包含：多用户账号、复杂权限、移动端原生应用、全文搜索引擎和复杂数据分析。

## 7. 非功能要求

- API Key 只存在于服务端环境变量，不进入前端代码、Git 或日志。
- 采集请求需要限频、超时、重试和缓存。
- 页面适配桌面、平板和手机。
- 重要状态必须有空状态、加载状态和错误状态。
- 支持 `prefers-reduced-motion`。
