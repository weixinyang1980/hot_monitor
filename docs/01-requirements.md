# Hot Monitor 当前需求

## 1. 产品定位

Hot Monitor 是一个面向 AI 编程内容创作者的热点监控工具。它按监控关键词采集公开信息，做基础的相关性和技术内容判断，并把结果展示在 Web 页面中。

目前更关注把单机版扫描、查看和通知流程跑通，结论仅供参考。

## 2. 当前支持的使用方式

用户可以：

- 新增、启用、暂停和删除监控关键词。
- 暂停监控关键词后，列表立即移除与该关键词关联的热点；重新启用后可再次查看当前扫描快照中的关联结果。
- 手动发起一次扫描。
- 查看当前扫描得到的热点列表，并打开原始来源。
- 看到来源、关键词、标题和摘要。
- 通过页面看到服务状态、来源状态、扫描状态和下一次扫描时间。

系统也会在每个半小时进行一次自动扫描。当前扫描是全量快照：开始扫描时会清空旧的热点匹配，再写入本次扫描结果，因此列表不用于长期累积历史记录。

## 3. 信息来源

当前实现包含以下来源：

- RSS：官方 AI/开发者博客与经筛选的技术媒体 RSS，例如 Hugging Face、OpenAI、Google AI、AWS、Microsoft、GitHub、TechCrunch AI、VentureBeat AI。
- 网页与新闻发现：配置 `FIRECRAWL_API_KEY` 后，通过 Firecrawl 搜索网页与新闻结果；仅接受可信域名中的结果。
- X/Twitter：配置 `TWITTERAPI_API_KEY` 后，通过 `twitterapi.io` 高级搜索按关键词的热门度获取信息。仅允许可信账号，或同时达到认证、粉丝和互动门槛的例外账号进入候选池。

RSS、网页或 X/Twitter 的单个来源失败时，其他来源仍可继续处理。每条信息会保存标题、原始 URL、来源名称、来源类型、发布时间和正文内容，并按 URL 和内容摘要去重。扫描会先进行关键词核心度、技术性、可信度和来源质量判断，再按来源配额选择最终主情报流；X 默认不超过主情报流的 35%，在没有其他来源时最多保留 2 条兜底信号。

### 3.1 热点时间范围

当前版本不使用所有来源共用的固定时间窗口，而是按来源定义候选内容的时效性：

- 网页与新闻发现：仅搜索最近 7 天发布或收录的结果。
- RSS：每个订阅源取最新 8 条，不额外按发布时间截断。
- X/Twitter：使用高级搜索的 `Top` 排序获取首页结果，不设置额外的明确时间上限；当前不使用游标继续翻页。

页面展示的是当前一轮扫描的结果快照，不是上述时间范围内的历史累积；手动扫描或每半小时自动扫描都会用新的筛选结果替换原列表。

## 4. 内容判断

配置 `DEEPSEEK_API_KEY` 后，系统会请 DeepSeek 判断信息是否与关键词相关、是否属于技术内容、关键词是否是内容核心主题，并生成相关性分数、核心度分数、可信度分数、分类、摘要、关键事实和判定理由。仅仅提及监控词的内容会被过滤。

模型返回内容需要通过 JSON 格式校验。没有配置 DeepSeek 时，系统使用简单的本地技术关键词规则；这类结果的可信度分数为 0。AI 调用失败或结果不合规时，信息会被过滤，不会作为高可信热点进入结果。

## 5. 通知

- 新的热点匹配写入后，通过 Socket.IO 推送给在线页面。

## 6. 当前版本范围

当前版本包括：

- React + Vite Web 控制台。
- Node.js + Express API。
- SQLite 数据持久化。
- RSS 与可选的 X/Twitter 采集。
- DeepSeek 可选接入和本地降级判断。
- 半小时自动扫描和手动扫描。
- Socket.IO 页面推送。
- 基础健康检查、扫描记录和自动化测试。

## 7. 基本约束

- API Key 只放在服务端环境变量中，前端只使用 `VITE_API_URL`。
- 采集请求设置 10 秒超时，DeepSeek 请求设置 30 秒超时。
- 页面适配桌面、平板和手机，并提供加载、空数据和扫描中的状态。
- 页面尊重 `prefers-reduced-motion` 设置。
