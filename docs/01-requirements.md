# Hot Monitor 当前需求

## 1. 产品定位

Hot Monitor 是一个面向 AI 编程内容创作者的热点监控工具。它按监控关键词采集公开信息，做基础的相关性和技术内容判断，并把结果展示在 Web 页面中。

目前更关注把单机版扫描、查看和通知流程跑通，结论仅供参考。

## 2. 当前支持的使用方式

用户可以：

- 新增、启用、暂停和删除监控关键词。
- 手动发起一次扫描。
- 查看当前扫描得到的热点列表，并打开原始来源。
- 看到来源、关键词、标题和摘要。
- 通过页面看到服务状态、来源状态、扫描状态和下一次扫描时间。

系统也会在每个半小时进行一次自动扫描。当前扫描是全量快照：开始扫描时会清空旧的热点匹配，再写入本次扫描结果，因此列表不用于长期累积历史记录。

## 3. 信息来源

当前实现包含以下来源：

- RSS：Hugging Face Blog、OpenAI News、Google AI Blog。
- X/Twitter：配置 `TWITTERAPI_API_KEY` 后，通过 `twitterapi.io` 按关键词获取信息。

RSS 或 X/Twitter 的单个来源失败时，其他来源仍可继续处理。每条信息会保存标题、原始 URL、来源名称、来源类型、发布时间和正文内容，并按 URL 和内容摘要去重。

## 4. 内容判断

配置 `DEEPSEEK_API_KEY` 后，系统会请 DeepSeek 判断信息是否与关键词相关、是否属于技术内容，并生成相关性分数、可信度分数、分类、摘要、关键事实和判定理由。

模型返回内容需要通过 JSON 格式校验。没有配置 DeepSeek 时，系统使用简单的本地技术关键词规则；这类结果的可信度分数为 0。AI 调用失败或结果不合规时，信息会被过滤，不会作为高可信热点进入结果。

## 5. 通知

- 新的热点匹配写入后，通过 Socket.IO 推送给在线页面。
- 配置 SMTP 和收件地址后，达到该关键词通知阈值的热点会尝试发送邮件。
- 邮件发送失败不会阻止扫描完成，也不会影响页面推送。

邮件和扫描阈值目前通过服务端环境变量或接口参数配置，不在页面内提供完整的配置界面。

## 6. 当前版本范围

当前版本包括：

- React + Vite Web 控制台。
- Node.js + Express API。
- SQLite 数据持久化。
- RSS 与可选的 X/Twitter 采集。
- DeepSeek 可选接入和本地降级判断。
- 半小时自动扫描和手动扫描。
- Socket.IO 页面推送和可选 SMTP 邮件通知。
- 基础健康检查、扫描记录和自动化测试。

## 7. 基本约束

- API Key 只放在服务端环境变量中，前端只使用 `VITE_API_URL`。
- 采集请求设置 10 秒超时，DeepSeek 请求设置 30 秒超时。
- 页面适配桌面、平板和手机，并提供加载、空数据和扫描中的状态。
- 页面尊重 `prefers-reduced-motion` 设置。
